# 내 편 — 분쟁 대응 에이전트

억울한 분쟁 상황을 자유 서술로 적으면, 쟁점을 뽑고 관련 법령·
소비자분쟁해결기준·한국소비자원 분쟁조정 사례를 실시간으로 조사해
근거를 정리한 뒤, 단계별 대응 문안(1단계 말 스크립트 → 2단계
문자·메일 문안 → 3단계 내용증명)과 상대의 예상 반박·재대응까지
만들어 주는 에이전트입니다.

.EXE-THON 2026 (Team Nexus) 출품작입니다.

## 핵심 원칙 — 근거를 두 단계로 나눠 표시합니다

"관련 기준이 검색됐다"와 "내 주장이 입증됐다"는 다른 문제라,
결과에서 둘을 분리합니다.

- (a) 기준 확인: 이 쟁점에 적용되는 법령·기준·사례가 존재한다는
  것이 출처와 함께 확인됐는가. Liner AI Search가 실제 출처 URL을
  돌려줬을 때만 "기준 확인됨"이 됩니다.
- (b) 주장 입증: 내 구체적 주장이 뒷받침되는가.
  - 기준형 주장(기준이 정한 환불·배상 방식 등)은 기준이 확인되면
    입증으로 봅니다.
  - 사실형 주장(상대의 책임, 피해 사실, 금액의 적정성 등)은 측정
    자료·영수증·기록 같은 사실 증거가 제시되지 않으면, 기준이
    확인돼도 "주장 입증 안 됨"으로 코드가 강제합니다.
- 출처는 정부·공공 도메인(.go.kr — law.go.kr, easylaw.go.kr,
  ftc.go.kr, kca.go.kr 등) 공식 출처를 앞에 정렬하고, 블로그·SNS·
  유튜브 같은 비공식 출처는 따로 표시합니다.
- 근거 요지는 화면 표시용으로 정리합니다. 마크다운 제목 기호,
  표 기호, 수식 기호 같은 잔재를 걷어낸 평문으로 보여 줍니다.
- 문안은 확인된 기준만 인용합니다. 입증 안 된 주장은 문안에서
  사실로 단정하지 않습니다.
- 이 도구는 정보 제공과 문안 작성 보조입니다. 법률 자문이 아닙니다.

## 기술 스택 — Liner API 활용

- 근거 조사: Liner AI Search API (`POST /agents/search`) — 근거 있는
  답변과 실제 검색 출처(references)를 함께 반환합니다. 출처는 모델이
  지어낸 문자열이 아니라 검색 결과의 URL을 그대로 씁니다.
- 쟁점 추출·주장 유형 분류·문안 생성: Liner Router API
  (`POST /chat/completions`, 모델 liner-gpt-router). Router는 웹
  검색을 하지 않으므로 근거 조사에는 쓰지 않습니다. 조사는 Search,
  구조화와 문안 작성은 Router가 맡습니다.
- 백엔드: FastAPI (Python), 스키마 검증은 pydantic.
- 판정 규칙(기준 확인, 주장 입증, 출처 정렬)은 LLM이 아니라 코드가
  강제합니다. 출처 없는 쟁점은 확인됨이 될 수 없고, 증거 없는
  사실형 주장은 입증됨이 될 수 없습니다.

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env   # LINER_API_KEY 입력
uvicorn app.main:app --port 8300
# 브라우저에서 http://localhost:8300
```

케이스 실행 (CLI):

```bash
python3 run_case.py samples/case1_gym.json samples/case1_gym_report.json
python3 run_case.py samples/case1_gym.json --mock   # 키 없이 폴백 확인
```

테스트:

```bash
python3 -m pytest tests/ -q
```

## API

- `GET /` — 입력 화면 (상황 서술, 자료 붙여 넣기, 결과 한 흐름 표시)
- `POST /analyze` — DisputeRequest → DisputeReport (요약, 쟁점,
  쟁점별 기준 확인/주장 입증 판정과 이유, 공식·기타 출처, 입증된
  주장과 입증되지 않은 주장, 단계별 문안, 예상 반박)
- `GET /health`
